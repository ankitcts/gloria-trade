01

Executive Summary & Project Scope

Gloria Trade is a full-stack, AI-powered securities trading platform that enables users to browse stock market securities, execute simulated trades, manage portfolios, and receive ML-driven price predictions. The platform features real-time WebSocket price streaming, interactive candlestick charts, and a comprehensive admin panel for user management.

Platform Strategy: Initially built as an Angular 19 application (production-ready), now being migrated to React 19 for long-term maintainability. Both share the same FastAPI + MongoDB backend.

Target Platforms

React 19 (Primary) Angular 19 (Legacy) FastAPI (Backend) MongoDB Atlas AWS EC2 (Deployment)

Core Features

Securities Browser

Searchable, filterable list of NASDAQ securities with real-time quotes, interactive candlestick charts (Lightweight Charts), fundamentals cards, and risk badges.

Simulated Trading

Place buy/sell orders with market/limit types. Real-time order fill simulation via WebSocket. Full order lifecycle: placed, partial fill, filled, cancelled.

Portfolio Management

Track holdings with real-time P&L calculation. Transaction history, portfolio summary cards, and per-holding detail views with cost basis analysis.

ML Price Predictions

PyTorch and scikit-learn models generate price forecasts, trading signals (buy/hold/sell), risk metrics, and confidence scores for each security.

Dashboard & Analytics

Summary cards for portfolio value, daily P&L, top movers. Recent orders feed, top securities by volume, and quick-action shortcuts.

Admin Panel

User management with CRUD, role assignment (admin/trader/viewer), status management, and group-based permission controls.

Key Architectural Principles

  • Modular monolith: All backend services live in one FastAPI application as separate router modules. Each module (auth, securities, trading, etc.) has its own router, service, and dependencies -- cleanly separable if microservices are needed later.
  • Shared data layer: All services share a single MongoDB Atlas cluster via Beanie ODM with Motor async driver.
  • Real-time via WebSocket: Trading simulation streams live price updates and order fills via FastAPI WebSocket endpoints.
  • Dual frontend support: Both Angular 19 (production-complete) and React 19 (in migration) consume the same API. The backend is frontend-agnostic.
  • ML as a service: Predictions pipeline runs alongside the API, using PyTorch and scikit-learn models stored in MongoDB.
  • Security-first auth: JWT access + refresh tokens, bcrypt password hashing, OTP verification for sensitive operations.

  username              : str (unique, indexed)
  hashed_password       : str                        # bcrypt hash
  full_name             : Optional[str]

  # Profile
  avatar_url            : Optional[str]
  phone                 : Optional[str]

  # Groups & Permissions

Real-Time Trading Engine

Gloria Trade simulates a live trading environment using WebSocket connections for real-time price streaming and order fill simulation.

7.1 Price Simulation Pipeline

[Client connects to WebSocket] | v /ws/trading/{security_id} | v [WebSocket Connection Manager] |-- Registers client to security channel |-- Starts price simulation loop | v [Price Simulation Engine] Runs every 1-3 seconds | |-- Fetch last known price from MongoDB |-- Apply random walk with drift: | new_price = price * (1 + drift + volatility * random_normal()) |-- Respect daily high/low bounds |-- Generate OHLCV tick data | v [Broadcast to all subscribers] { "type": "price_update", "symbol": "AAPL", "price": 198.42, "change": +2.31, "change_percent": +1.18, "volume": 45230, "timestamp": "2026-03-27T14:30:00Z" } | v [Order Matching Engine] Checks on each tick | |-- Scan open orders for this security |-- Market orders: fill immediately at current price |-- Limit orders: fill if price crosses limit |-- Stop orders: trigger if price crosses stop |-- Generate fill events: { "type": "order_fill", "order_id": "...", "fill_price": 198.42, "fill_quantity": 100, "status": "filled" }

7.2 WebSocket Connection Manager

class ConnectionManager:
    """Manages WebSocket connections per security channel."""

    active_connections: dict[str, list[WebSocket]]
    # Key: security_id, Value: list of connected clients

    Methods:
      connect(security_id, websocket)     # Add client to channel
      disconnect(security_id, websocket)  # Remove on close
      broadcast(security_id, data)        # Send to all in channel
      send_personal(websocket, data)      # Send to single client

    Features:
      - Auto-cleanup on disconnect
      - Heartbeat ping/pong every 30s
      - Auto-reconnect support (client-side)
      - Channel-based isolation (per-security)

08

ML Predictions Pipeline

8.1 Model Architecture

LSTM Price Predictor (PyTorch)

  • Input: 60-day OHLCV window + technical indicators
  • Architecture: 2-layer LSTM (128 hidden) + Dense
  • Output: Next-day price prediction
  • Training: Rolling 1-year window, retrain weekly
  • Features: SMA(20), EMA(12), RSI(14), MACD, Bollinger Bands

Random Forest Signal Generator (scikit-learn)

  • Input: 30 technical + fundamental features
  • Output: Signal classification (strong_buy to strong_sell)
  • Ensemble: 200 trees, max_depth=15
  • Features: P/E ratio, volume changes, moving averages, momentum indicators
  • Confidence: Probability from tree voting

8.2 Prediction Pipeline

[Scheduled Daily Trigger] Runs at market close (4:00 PM ET) | v [Fetch Latest Market Data] |-- yfinance: OHLCV for all tracked securities |-- Calculate technical indicators (SMA, EMA, RSI, MACD, BB) |-- Fetch fundamental data (P/E, EPS, beta) | v [Feature Engineering] |-- Normalize prices (MinMaxScaler per security) |-- Create 60-day sliding windows (LSTM) |-- Build feature matrix (Random Forest) |-- Handle missing values (forward fill) | v [Model Inference] (run in parallel) | |-- LSTM Price Predictor: | Input: [batch_size, 60, num_features] tensor | Output: [batch_size, 1] predicted prices | |-- Random Forest Classifier: | Input: [num_securities, 30] feature matrix | Output: [num_securities] signal + confidence | v [Risk Analysis] |-- Calculate portfolio volatility (SciPy) |-- Compute Sharpe ratio per security |-- Estimate max drawdown from historical data |-- Generate risk_score (0-1) composite metric | v [Store MLPrediction Documents] One per security per day | v [API serves via /api/v1/predictions]

Authentication & Security

9.1 JWT Token Flow

[User Login] POST /api/v1/auth/login Body: { email, password } | v [Server Validates] |-- Find user by email |-- Verify bcrypt hash: passlib.verify(password, hashed_password) |-- Check user status == "active" | v [Generate Token Pair] |-- Access Token: JWT { user_id, role, exp: 15min } |-- Refresh Token: JWT { user_id, type: "refresh", exp: 7days } |-- Store session: UserSession { user_id, token_hash, device, ip } | v [Response] { "access_token": "eyJ...", "refresh_token": "eyJ...", "token_type": "bearer", "expires_in": 900 } | v [Client stores in Zustand (React) / Signal (Angular)] |-- authStore.setTokens(access, refresh) |-- Persist to localStorage for page reload | v [Axios/HttpClient Interceptor] |-- Request: Authorization: Bearer {access_token} |-- Response 401: Auto-refresh using refresh_token |-- Refresh fails: Redirect to /login

9.2 OTP Verification (Sensitive Operations)

Two-factor verification for high-risk actions in the Angular version.

Triggers:
  - First-time login from new device
  - Password change
  - Large trade orders (configurable threshold)
  - Admin role actions

Flow:
  1. POST /api/v1/auth/request-otp → sends 6-digit code via email
  2. OTP Document stored: { user_id, code (hashed), expires_at (5min) }
  3. User enters code in OTP dialog
  4. POST /api/v1/auth/verify-otp → validates, returns elevated session
  5. Max 3 attempts, then new code required

9.4 Security Measures

  • Password hashing: bcrypt via Passlib with automatic salt
  • JWT signing: HS256 with configurable secret key
  • CORS: Configurable allowed origins (dev: localhost:3000/4200, prod: domain)
  • Rate limiting: Nginx-level rate limits on auth endpoints
  • Input validation: Pydantic models validate all request bodies
  • SQL injection: N/A (MongoDB + Beanie ODM with parameterized queries)
  • XSS prevention: React auto-escapes, Angular sanitizes by default

11.2 Migration Order

Strategy: Migrate bottom-up starting from the shared layer, then independent features, and finally pages that depend on multiple features.
  1. Shared Layer -- TypeScript types, API client (Axios), auth store (Zustand), theme config
  2. Securities -- Most complex standalone feature, no cross-feature dependencies
  3. Portfolio, Watchlist, Notifications, Predictions -- Can be migrated in parallel (independent features)
  4. Trading -- Depends on Securities + Portfolio
  5. Admin -- Standalone but lower priority
  6. Dashboard -- Migrated last as it composes widgets from all other features
  7. Layout / Shell -- AppShell, Header, Sidebar wrap around all features

Key Architectural Decisions

DecisionChoiceRationale
Primary Frontend React 19 + Vite Larger ecosystem, easier hiring, better DX with hooks. Angular version serves as production reference during migration.
State Management Zustand + React Query Zustand for client state (auth, theme) is minimal and fast. React Query for server state adds automatic caching, background refetch, and optimistic updates without boilerplate.
UI Library MUI v6 Closest Material Design mapping to Angular Material. Comprehensive component set (DataGrid, Dialog, Drawer) covers all trading UI needs.
Charting Lightweight Charts (TradingView) Purpose-built for financial data. Candlestick, volume, technical indicators out of the box. Same library used in Angular version.
Database MongoDB Atlas Flexible document schema suits diverse models (users, orders, predictions). Beanie ODM provides Pythonic async access. Atlas handles backups, scaling, monitoring.
Backend Framework FastAPI Async-first, auto-generates OpenAPI docs, Pydantic validation, native WebSocket support. Perfect for real-time trading data.
ML Framework PyTorch + scikit-learn PyTorch for LSTM time series models, scikit-learn for ensemble classifiers. Both run in-process (no separate ML service needed at current scale).
Real-Time Protocol WebSocket (FastAPI native) Lower latency than polling for price streaming. Built into FastAPI, no external broker needed. Channel-based isolation per security.
Auth Strategy JWT (access + refresh) + OTP Stateless access tokens for API calls. Refresh tokens for seamless re-auth. OTP adds security for sensitive operations without a third-party auth provider.
Market Data yfinance (free) Sufficient for development and demo with NASDAQ data. Can upgrade to paid APIs (Alpha Vantage, Polygon.io) for production real-time data.
Backend Pattern Modular monolith All modules (auth, trading, portfolio, etc.) in one FastAPI app with separate routers. Clean boundaries allow microservice extraction if needed.
Migration Approach Bottom-up, feature-by-feature Shared layer first, then independent features in parallel, then composed pages. Backend stays unchanged -- only the frontend is migrated.
This is a living document. Architecture decisions will be revisited as the migration progresses and the React application matures. Each phase completion triggers a review to validate assumptions and adjust course.
